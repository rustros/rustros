安装到云主机

在一台装着 Linux、用 GRUB 启动的 x86_64 云主机（KVM，virtio 磁盘和网卡）上，以 root 运行：

curl -fsSL https://rustros.com/install.sh | sh

安装分两步，中间可以停下来：

  1. 准备并试启动。脚本下载最新发布版，用内置的公钥校验签名、逐个核对 SHA-256，按这台机器现在的网络（Linux 用 DHCP 就用 DHCP，否则沿用当前的静态地址）做出磁盘镜像，生成更新密钥，然后让 GRUB 只引导 RustROS 一次。试启动不写磁盘，5 分钟后自动重启回 Linux。这段时间里它应该能 ping 通；云控制台（VNC）上能看到它识别到的网卡和地址。
  2. 写盘。回到 Linux 后确认没问题，再运行： 
    python3 /root/rustros/install.py --write
    它会要求输入 yes，然后把镜像写到系统盘并重启进 RustROS。这块盘上原来的一切都会丢失。UEFI 机器会先把固件自己的磁盘启动项排到最前面。
更新密钥会打印出来，也保存在 /root/rustros/update.key。写盘后 Linux 就没了，先把密钥复制到别处——在线更新和远程管理都要用它。

要求

  • x86_64，至少 2 GiB 的系统盘（根文件系统直接在磁盘分区上，不支持 LVM/RAID）
  • GRUB 2 引导；BIOS 或 UEFI 都行，UEFI 要关掉 Secure Boot
  • python3 和 OpenSSL 3（Debian 12、Ubuntu 22.04 及以后都自带）
  • virtio 网卡和磁盘（KVM 云主机基本都是）。有多块网卡时 RustROS 用第一块

选项

通过 sh -s -- 传给脚本，例如 curl -fsSL https://rustros.com/install.sh | sh -s -- --apps ext4,shell,webadmin：

选项作用
--apps a,b首次启动时安装的应用（默认 ext4,shell）
--ip A/N --gw G静态地址
--dhcp用 DHCP
--panel URL接入管理面板
--key K指定更新密钥（默认随机生成）
--no-test跳过试启动
--yes不询问（试启动后直接重启；写盘时不要求输入 yes）

在 QEMU 里试

每个发布版都有一个磁盘镜像 rustros-x86_64.img（发布页上有链接）。把它扩到 2 GiB 以上再启动：

truncate -s 2G rustros-x86_64.img
qemu-system-x86_64 -m 256 -nographic \
  -drive file=rustros-x86_64.img,format=raw,if=virtio \
  -nic user,model=virtio-net-pci

它会用 DHCP 取地址。这个镜像里没有更新密钥，所以在线更新不可用；控制台和其他功能都正常。

控制台

串口和显示器上都是同一个控制台。开机先进 rescue（内置的救援控制台）；装了 shell 应用后控制台交给它，提示符变成 rustros>。Ctrl-] 在两者之间切换。help 列出命令。

shell 常用命令：

ip / arp / conns网卡与计数、ARP 表、连接和监听端口
ping / curl连通性测试；curl 支持 HTTPS
mod / modules已安装 / 正在运行的模块
cfg <应用> [键 [值 | -]]查看、设置、删除应用的设置；密码类的键不带值时会隐藏输入
pkg ...包管理，见下文
log / crash每次启动的控制台日志（保存在磁盘上）/ 最近一次崩溃
slot / confirm内核 A/B 槽；确认正在试运行的内核
df / uptime / date存储用量、运行时间、时间
reboot / poweroff

网络设置

改网络有“候选配置”保护，改错了不会把自己锁在外面：

cand ip nic0 203.0.113.10/24 203.0.113.1
apply          # 生效，然后问你要不要保留；10 秒内不回答 yes 就恢复原样
save           # 写进 GRUB 环境块，重启后也用它

直接 ip nic0 A/N GW 立即生效但不保存，重启恢复。ip nic0 add A 给网卡加额外地址（NAT 出口用）。

应用与 pkg

功能都在模块里，内核只带 rescue、dhcp 和 updater。应用、文件系统驱动（ext4）、WebAssembly 运行时都是模块，从签名的发布版安装：

pkg update            # 读取最新清单并校验签名
pkg list              # 已装版本、可用版本、哪些能升级
pkg install nat router wireguard
pkg upgrade           # 升级所有能升级的应用
pkg upgrade kernel    # 新内核写进备用槽，重启试运行，confirm 后保留
pkg remove cake

应用的设置都用 cfg 查看和修改，例如 cfg nat 列出 NAT 的所有设置和说明。

在线更新与远程管理

用 rustros-update.py（Python 3，无依赖）从另一台机器管理，流量用更新密钥加密：

export RUSTROS_KEY=$(cat update.key)
python3 rustros-update.py 203.0.113.10 info
python3 rustros-update.py 203.0.113.10 upload rustros-x86_64.elf --wait
python3 rustros-update.py 203.0.113.10 module-install nat nat-x86_64.mod
python3 rustros-update.py 203.0.113.10 module-config webadmin allow 198.51.100.7
python3 rustros-update.py 203.0.113.10 log prev

upload --wait 把内核写进备用槽，重启试运行一次，起来后自动确认。新内核起不来或没确认，下次启动就回到原来的内核；连续三次启动不稳定会进安全模式，第四次换回另一个槽。

镜像默认 2 MiB，两个内核槽各 256 KiB。以后需要更大的槽时，esp-grow 8 1024 在线把 EFI 分区扩到 8 MiB、槽扩到 1 MiB，不丢数据：新分区先在空闲的启动区里写好并校验，最后才切换分区表，中途断电也能照常启动（需要 dosfstools 和 mtools）。

网页管理

装上 webadmin 后在 8080 端口提供网页管理，每个应用的设置页按它声明的参数自动生成。默认只允许没有网关的网卡所在网段访问，所以在云主机上要先放行自己的地址并设置密码：

pkg install webadmin
cfg webadmin allow 198.51.100.7
cfg webadmin password      # 输入两次，不回显

面板

panel 应用把机器接入管理面板：面板可以查看状态、安装和配置应用、更新内核。安装时用 --panel https://面板地址，或者之后 cfg panel url https://面板地址。第一次连接时控制台会显示认领码，在面板上输入即可认领。面板下发的下载只能来自 cfg panel downloads 指定的前缀（默认 https://rustros.com/）。

存储

位置内容
0 – 64 MiB引导区：GPT、GRUB、两个内核槽、随镜像带的应用
64 – 512 MiB缓存分区：每次启动的控制台日志
512 MiB – 1 GiB数据分区：崩溃安全的键值存储（设置、已安装的应用）
1 GiB – 磁盘末尾文件分区：标准 ext4，带 jbd2 日志和元数据校验（metadata_csum、64bit），应用各有自己的目录

分区都在第一次启动时创建。文件分区由文件系统驱动模块挂载（现在是 ext4；没装驱动时文件分区不挂载，其他功能照常）；它认不出的分区不会被格式化。文件分区可以拿到 Linux 上直接挂载和 e2fsck；Linux 用默认参数格式化的 ext4，RustROS 也能读写。

安全

  • 发布清单用 Ed25519 签名，公钥内置在安装脚本、pkg 和面板应用里；每个文件都核对 SHA-256。
  • 在线更新和远程管理的流量用更新密钥认证和加密。
  • 更新密钥以明文保存在磁盘的 GRUB 配置里：能读这块盘的人就能拿到它。
  • 内核之外的代码都是 #![forbid(unsafe_code)] 的 Rust。

许可

RustROS 是闭源的专有软件（许可条款）：这里发布的内核、模块和镜像可以免费装在自己的机器上使用，不能转卖、再分发或逆向。

其中用到的第三方软件按各自的许可使用，版权声明和许可全文见 THIRD-PARTY-NOTICES.txt。镜像里的引导程序 GRUB 是 GPLv3 的自由软件，它的源码随版本发布，下载地址见上面的第三方声明。

Install on a VPS

On an x86_64 VPS running Linux and booting with GRUB (KVM, virtio disk and NIC), as root:

curl -fsSL https://rustros.com/install.sh | sh

It goes in two steps, with a stop in between:

  1. Prepare and test-boot. The script downloads the latest release, checks its signature against the key built into it and every file's SHA-256, makes the disk image with this machine's network (DHCP if Linux uses DHCP, else the static address it has now), makes an update key, and has GRUB boot RustROS once. The test boot does not write the disk and restarts into Linux after 5 minutes. Meanwhile it should answer ping; the cloud console (VNC) shows the NICs and address it found.
  2. Write the disk. Back in Linux, if it worked: 
    python3 /root/rustros/install.py --write
    It asks you to type yes, writes the image over the system disk and restarts into RustROS. Everything on that disk is lost. On UEFI machines the firmware's own disk entries are put first in the boot order.
The update key is printed and kept in /root/rustros/update.key. Once the disk is written Linux is gone: copy the key somewhere else first — online updates and remote management need it.

Requirements

  • x86_64, a system disk of 2 GiB or more (the root file system on a plain partition: no LVM or RAID)
  • GRUB 2; BIOS or UEFI, with Secure Boot off
  • python3 and OpenSSL 3 (Debian 12, Ubuntu 22.04 and later have them)
  • virtio NIC and disk (as KVM clouds give). With several NICs RustROS uses the first

Options

Passed through sh -s --, e.g. curl -fsSL https://rustros.com/install.sh | sh -s -- --apps ext4,shell,webadmin:

OptionWhat it does
--apps a,bapps installed at first boot (default ext4,shell)
--ip A/N --gw Ga static address
--dhcpDHCP
--panel URLconnect to a management panel
--key Kthe update key (default: a new random one)
--no-testno test boot
--yesdo not ask (reboot for the test straight away; no typed yes before writing)

Try it in QEMU

Every release has a disk image, rustros-x86_64.img (linked on the releases page). Grow it to 2 GiB or more and boot it:

truncate -s 2G rustros-x86_64.img
qemu-system-x86_64 -m 256 -nographic \
  -drive file=rustros-x86_64.img,format=raw,if=virtio \
  -nic user,model=virtio-net-pci

It gets its address by DHCP. The image has no update key, so online updates are off; the console and everything else work.

The console

The serial port and the screen show the same console. It starts in rescue, the built-in console; once the shell app is installed the console is its, with the prompt rustros>. Ctrl-] switches between them. help lists the commands.

The shell's everyday commands:

ip / arp / connsNICs and counters, the ARP table, connections and listening ports
ping / curlconnectivity; curl speaks HTTPS
mod / modulesinstalled / running modules
cfg <app> [key [value | -]]show, set or remove an app's settings; a password key without a value asks for it, hidden
pkg ...the package manager, below
log / crasheach boot's console log (kept on disk) / the last crash
slot / confirmthe A/B kernel slots; keep a kernel on trial
df / uptime / datestorage use, uptime, the time
reboot / poweroff

Network settings

Network changes go through a candidate, so a mistake does not lock you out:

cand ip nic0 203.0.113.10/24 203.0.113.1
apply          # in effect, then it asks; no "yes" within 10 s and it goes back
save           # into the GRUB environment block: kept across reboots

ip nic0 A/N GW applies at once but is not saved. ip nic0 add A adds an address (for NAT egress).

Apps and pkg

What RustROS does is in modules; the kernel carries only rescue, dhcp and the updater. Apps, file system drivers (ext4) and the WebAssembly runtime are modules, from the signed releases:

pkg update            # the latest manifest, signature checked
pkg list              # installed and available versions, what can be upgraded
pkg install nat router wireguard
pkg upgrade           # every app with a newer version
pkg upgrade kernel    # the new kernel into the spare slot: reboot to try it, confirm to keep it
pkg remove cake

Reading the list of apps…

Every app's settings are shown and changed with cfg: cfg nat lists NAT's settings with what each does.

Online updates and remote management

rustros-update.py (Python 3, no dependencies) manages a machine from another one; the traffic is authenticated and encrypted with the update key:

export RUSTROS_KEY=$(cat update.key)
python3 rustros-update.py 203.0.113.10 info
python3 rustros-update.py 203.0.113.10 upload rustros-x86_64.elf --wait
python3 rustros-update.py 203.0.113.10 module-install nat nat-x86_64.mod
python3 rustros-update.py 203.0.113.10 module-config webadmin allow 198.51.100.7
python3 rustros-update.py 203.0.113.10 log prev

upload --wait writes the kernel into the spare slot, boots it once and confirms it once it is up. A kernel that does not come up, or is not confirmed, is followed by the old one at the next boot; after three unstable boots it starts in safe mode, at the fourth the other slot takes over.

Images are 2 MiB with two 256 KiB kernel slots. Should the slots ever be too small, esp-grow 8 1024 grows the EFI partition to 8 MiB and the slots to 1 MiB online, losing nothing: the new partition is written and checked in the free boot area first, and only then does the partition table switch to it, so a power cut at any point still boots (needs dosfstools and mtools).

Web admin

The webadmin app serves a web admin on port 8080; each app's page is generated from the settings it declares. By default only the networks of NICs without a gateway may connect, so on a VPS allow your own address and set a password first:

pkg install webadmin
cfg webadmin allow 198.51.100.7
cfg webadmin password      # asked twice, not shown

Panel

The panel app connects the machine to a management panel, which shows its state, installs and configures apps and updates the kernel. Install with --panel https://your-panel, or later cfg panel url https://your-panel. On first contact the console shows a claim code to enter in the panel. What the panel has it download must come from cfg panel downloads (default https://rustros.com/).

Storage

WhereWhat
0 – 64 MiBthe boot area: GPT, GRUB, two kernel slots, apps carried by the image
64 – 512 MiBcache partition: each boot's console log
512 MiB – 1 GiBdata partition: a crash-safe key-value store (settings, installed apps)
1 GiB – the endfiles partition: a standard ext4 with a jbd2 journal and metadata checksums (metadata_csum, 64bit); each app has its own directory

The partitions are made at first boot. A file system driver module mounts the files partition (ext4 for now; without one it stays unmounted and the rest works as usual); a partition it does not recognise is never formatted. Linux mounts and e2fscks the files partition as it is, and RustROS reads and writes ext4 that Linux formatted with its defaults.

Security

  • Release manifests are signed with Ed25519; the public key is built into the installer, pkg and the panel app; every file's SHA-256 is checked.
  • Online updates and remote management are authenticated and encrypted with the update key.
  • The update key is kept in plain text in GRUB's configuration on the disk: whoever reads the disk has it.
  • Outside the kernel, all code is Rust with #![forbid(unsafe_code)].
